## Source and environment

The latest published GitHub release was [Mushak 0.0.11](https://github.com/divyangchauhan/Mushak/releases/tag/v0.0.11), dated 21 November 2026. The [release notes](../releases/0.0.11.md) identify the corresponding Store package as 1.0.11.0. I fetched remote branches and tags. The shipped tag points to `096d2c1693a3d390a7059dbd558aaa5274a05c88`. Its first parent, `44890726fc65b61f488b3dc8074c3dc56813a10b`, contains the settings redesign. Its second parent, `f8bcc6cfae3f06a634deb73312f1f6c18e82fe9a`, carries the earlier Store device fixes.

Fetched `origin/main` was `a1d161dc58795119f099aac7128fbc60084b788c`. Its merge base with the tag was `4489072`. Main did not contain the release merge. The release branch continued to `67b8150a1ad19588ffe25b0838a19f567ac895c0` with four Scoop and WinGet manifest edits. I based the isolated `design/interaction-review` worktree on the shipped tag so the baseline contains both parents. The original checkout and installed resident remained in place.

The GPU gallery uses the production Settings render and input paths with isolated sample settings. The normal client is 968 × 668 logical pixels, the compact client is 720 × 540, and the live-resize stress case is 720 × 360. Windows 26H2 build 26300.10075 reported 192 DPI, or 200%, on a 3000 × 1876 display. Settings captures are lossless WebP at logical resolution. The tray captures preserve native physical menu pixels. There was one active display scale. Dark and Light are the two Settings themes. Both use Marigold for these comparisons. The three optional accent values in the preferences file were not included. The native Windows menu rendered light even though Windows had both its application and system light-theme switches set to 0. The gallery records the actual menu appearance.

Each stage has a `captures.json` with dimensions, scale, theme and device state for each image. The connected 2S GUI replays a recorded Bluetooth report. The 3S, 4, extra control, generic USB mouse, missing device and conflict states use simulated reports. Mushak discovers the current mouse automatically. It has no device-selection menu. The availability of wheel, DPI and gesture controls follows the reported capabilities.

A separate read-only diagnostic identified the **physical** Wireless Mouse MX Master 2S over Bluetooth, at 1000 DPI, with four remappable controls. In one discovery pass the mouse omitted DPI support. A read twelve seconds later returned the DPI capability and 1000 DPI. The [physical device readings](physical-device.json) record both. All remapping, DPI and gesture interactions below use isolated sample settings. Physical button actuation, on-device wheel-mode changes and gesture recognition were not verified in this review.

## Independent reviews

OpenAI `gpt-6.2-astra` implemented the changes and had no vote. The reviewers were `gpt-6.2-sol`, `gpt-6.1-terra` and `gpt-6-astra`. Each reviewed a neutral, single-version packet in a fresh context. They opened the actual rendered pixels, including both themes and ordered shortcut frames in both themes. They did not receive a target, stage number, prior score or another reviewer's comments. The fixed anchors were 8 for a good screen with a material issue, 9 for excellent and 10 for exceptional.

Every stage has 42 ballots. For rounds 5 through 10, the live councils inspected all 14 groups and scored each changed group. Separate blind passes later scored the archived, unchanged groups from those rounds. Each reviewer received the six anonymized historical packets in a different order and graded each on its own. The CSV identifies these retrospective ballots. All 1722 group ratings use the actual stage pixels. Each ballot includes eight scores, a visible label, a specific detail and any remaining concern.

The six individual tab switches can also be replayed in the ordered gallery, in both themes, using real Windows Settings processes. For the shipped side I downloaded the published mushak.exe and matched its SHA-256, aecf312a4a89909b372186a0bbb1c594b46b968c86b419b785ef540149235f7f. All three reviewers separately inspected those twelve extra captures. Their [supplementary observations and scores](baseline/native-cycle-reviews.json) do not replace the baseline ballots. ## Remaining visual findings

- Shell and profile switcher (8/10). The menu does not identify the profile currently in effect. Edit profile names the editing scope, but the lone check could also read as runtime status. The selector labels the editing profile, but the screen does not identify the currently active profile.
- Button artwork and reported controls (8/10). The control ID alone gives no way to identify the physical button. Naming helps after the user has worked out which button it is. An unlocated control remains difficult to identify physically, even with its reported ID and naming flow. Button 0x01FF and Native action do not tell the user how to identify or test the physical control. The naming dialog helps organize it but leaves that discovery problem unresolved.
- Button mapping list (8/10). Compact mode drops the diagram while retaining number badges. The numbers have no visible reference in this view. The compact list removes the mouse illustration, so the numbered items no longer show physical locations.
- Action editor and categories (8/10). Selecting a draft removes the check from the currently assigned row, and the heading switches to Unsaved. The previous assignment becomes harder to verify before saving. The action list scrolls inside a small panel and its last visible row is clipped at the footer. The category and action regions have narrow independent scroll areas, and the compact picker shows a strong category scrollbar even with only six categories. The layout makes browsing feel more constrained than its surrounding empty space warrants.
- Action search (8/10). The results use a small Select text label while category rows omit it. The change in row treatment weakens the cue that both are selectable. The result uses a separate Select label, unlike the category list, so selection behavior is less consistent.
- Wheel button actions (7/10). The compact footer cuts into the second speed row and the Current and Next press readouts sit below the visible area. The checked wheel action also uses different wording in the draft header. In the short compact dialog the sticky footer covers part of Speed 2 and the current/next values require scrolling. At 720 by 360, the fixed footer visibly cuts through the second DPI input and the current/next-press summary falls below the viewport. The wheel action label also changes from Toggle ratchet and free-spin to Shift wheel mode in the draft header.
- Wheel settings (8/10). Disabled sliders become very faint, although adjacent text explains how to enable them. The nudge threshold has only off and 100% endpoints, so users cannot infer how its intermediate values will feel without testing. Compact radio cards also crowd their descriptions against the radio circles.
- Gestures (8/10). When gestures are off the rows remain editable while the distance slider is disabled, a distinction conveyed mostly by small text. The trigger instruction refers to button 4 on another page without a direct visual or link here. A user who does not already know the gesture button must leave this page to locate it.
- Profiles and window capture (8/10). The countdown and extension controls live inside Mushak, where they may no longer be visible after switching to the target window. The shown capture state gives no preview of the app it will add. Window capture requires switching away before a timer expires, and the chosen target is not visible during that interval. Capturing whichever app is active when a timer ends requires time-sensitive window switching. It offers no visible target preview or confirmation before adding the process.
- Device status (8/10). The DPI slider has no visible numeric entry, making precise adjustment harder than dragging. Pointer speed uses a slider and numeric readout with no visible direct-entry field. Reaching an exact DPI value is less obvious here than in the wheel-button DPI editor.
- Device diagnostics (8/10). Copy unnamed IDs sits at the top while its contents sit below the fold in compact mode. The shown screens give no destination or confirmation after a copy. The two-column ID list lacks column headers or explanations for the identifiers, and compact view puts unnamed IDs below the fold. The two-column list has row dividers but no column headings or clear reading order. The raw unnamed IDs form a dense block, and compact height places that block below the fold.
- Conflict and feedback (8/10). The warning and its Quit control sit at the bottom while Resume and Retry sit in the title bar. In Resume failed, the instruction refers to Retry but the actual control is outside the help page. The conflict and paused state occupy opposite edges of the window, and dismissing the banner removes the explanation while the pause remains. Pause status and Resume are small controls in the title bar, far from the bottom conflict banner that tells users to resume. The fallback instructions refer to the Mushak tray icon without showing what it looks like.
