What changed after review

The original button labels competed with the mouse artwork. Numbered markers now lead to a separate assignment list. Opening a mapping keeps the selected control in view. The original MX Master and 2S use a close-up for the two buttons behind the thumb wheel. Extra firmware controls without an artwork position have their own editable row.

The compact mapping editor first clipped its last row, then left a four-item page half empty. Eight complete tiles now fit per page. Distinct key combinations replaced the repeated editing icons. The desktop editor groups button behavior and common shortcuts separately and moves the other categories into a menu. In Edit, a single instruction introduces the list. Each action has its own full-width button, with the Windows shortcut aligned on the right.

The profile cards now follow first-match order. Named controls change that order, and a live banner lets the user cancel a window pick. Device diagnostics have their own view, and disconnected screens explain which mappings are still editable. The scorecards above retain the objections from each round, including dissenting final votes.

Capture and scoring

Settings screenshots use the app's production Ply layout, fonts, assets and GPU renderer, with synthetic pointer input and isolated APPDATA. The reference size is 968 by 668 logical pixels at 200% Windows scaling. The compact pair uses 720 by 540 at the same scale. Lossless WebP files show the captured pixels resampled to logical size. Click either image to open it. All gallery device, connection, battery, pause, conflict and profile states are fixtures. The MX Master 2S fixture comes from the repository's recorded Bluetooth device report. The menu captures show the actual Windows popup, with simulated tray state and the operating system's menu appearance.

The council used three OpenAI models in fresh sessions. Each reviewer opened the image sheets and supplied a visible label and visual detail. Dark and Light form a single group vote, and a material issue in either theme counts. Overall is a separate judgment. An 8 means a good screen with a material issue, 9 means excellent, and 10 means exceptional. The median is the middle of three independent Overall votes. Reviewers received neutral packet names, the rubric, and no earlier scores, peer comments or target. The supplemental baseline and first-round packets were shown in mixed order. The implementer, gpt-6.2-astra, cast no votes.

The original council packets covered 32 groups. Profile priority controls and the shared window shell received separate votes starting in round 3. Filtered search results and active key recording received separate votes starting in round 6. All four have baseline images. Round 9 introduced the action category selector. Round 13 gave the category menu its own review. Their before images show the original editor, which listed the editing actions alongside the other presets. The shell uses the Device view to show its title bar, navigation and status in context.

Foreground window capture

The Windows release build added ProfileSample.exe to the Preview app profile after the four-second countdown. The test used isolated settings and a real sample window. Hardware and verification limits

Read-only discovery reached a physical Wireless Mouse MX Master 2S over Bluetooth and returned its controls, sensor and wheel capabilities. The release executable opened with a live report and a copy of the saved sample configuration. A separate test replayed the recorded device report so the full set of buttons stayed available. Windows pointer messages selected Preview app, assigned Copy to its Back button, changed a modifier and closed the editor. The saved file retained Copy. The test restarted the release executable and reopened Preview app. See the reopened release window.

The app follows the single device reported by its resident process, so there is no device-selection control to test. The selection menu in Buttons chooses a profile.

Physical button presses, swipes, wheel feel, startup registration, terminating another application and other physical mouse models were outside the verified interaction set. The Windows desktop interaction helper failed to launch. The GPU tests supplied pointer input to the layout engine. The release test posted Windows messages to its own settings window. The gallery covers both supported app themes with the default accent. Other stored accent choices and display scales have no separate visual votes.
